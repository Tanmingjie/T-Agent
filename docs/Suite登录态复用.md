# Suite 登录态复用

Suite 可以指定一条现有用例作为“登录准备用例”。每次执行完整 Suite、选择多条业务用例
或执行单条业务用例时，平台先执行一次登录用例，再把该登录状态提供给本次 Run 中的业务用例。

## Excel 编写

在原 Excel 中增加一行普通用例，例如：

| 用例编号 | 用例名称 | 预置条件 | 测试步骤 | 预期结果 |
|---|---|---|---|---|
| LOGIN-001 | 标准用户登录 | 用户未登录 | 打开登录页；输入用户名和密码；点击登录 | 页面进入登录后的首页，显示当前用户名 |

登录用例必须能独立执行，并用页面可观察结果确认登录成功。它不需要特殊列或固定编号。

业务用例中应删除重复的输入账号、密码和点击登录步骤。需要表达前提时，可把预置条件写成
“用户已登录”；预置条件只提供翻译背景，不会再次执行登录。

## Suite 设置

1. 上传包含登录用例和业务用例的 Excel。
2. 打开 Suite 的“设置”。
3. 在“执行设置”的“登录准备用例”中选择登录用例。
4. 选择“不使用”可关闭该能力。

配置后，执行完整 Suite、部分所选用例或任意单条业务用例都会先执行该登录用例。登录用例
无需在多选列表中额外勾选；如果已经勾选，平台仍只执行一次。直接执行登录用例本身时，它也
只执行一次。Run 的实际用例总数包含自动加入的登录准备用例。

## 执行规则

- 登录用例成功后，平台捕获 Playwright `storageState`，包含 Cookie、localStorage 和 IndexedDB。
- 每条业务用例仍使用独立 BrowserContext，只加载相同的初始登录状态，不共享页面运行副作用。
- 登录用例失败或认证状态捕获失败时，业务用例不会启动，结果中会标记为“未执行”。
- 状态仅在当前 Run 内有效，Run 完成、失败、中止或异常后都会删除，不跨 Run 复用。
- `storageState` 不包含 `sessionStorage`。如果系统只在 `sessionStorage` 中保存登录凭据，当前能力
  无法复用该登录状态。
