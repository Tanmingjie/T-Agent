## Why

Midscene 集成后，精准用例已经可以完成基础操作和断言，但同一用例每次执行仍会重新翻译、重新理解业务语义并重新探索页面，导致翻译漂移、执行耗时偏高和稳定性波动。试点反馈表明，成功执行后的 TestSpec、等待经验、业务术语解释和避免重复点击等信息有复用价值，应沉淀为同一用例后续执行的经验资产。

## What Changes

- 成功执行的用例在内容未变化时沉淀并复用已验证通过的 TestSpec，减少重复翻译和翻译结果细微差异。
- 成功执行后总结用例级执行经验，包括业务术语解释、稳定操作提示、等待策略和断言注意事项。
- 后续同一用例命中成功经验时，将经验作为执行上下文强制注入 Midscene 链路，帮助模型更快、更准确地执行。
- 经验资产支持查看、禁用和重新翻译；禁用后本次执行不复用成功 TestSpec，也不注入成功经验。
- 用例内容、预期、base_url、项目版本等关键输入变化后，既有经验自动失效或不命中。
- 命中经验后若连续失败，系统标记经验可能过期，并允许用户回退到原始翻译执行。
- 不做半确定性回放、坐标回放、Playwright 动作录制回放或模型底层性能优化。

## Capabilities

### New Capabilities

- `case-execution-memory`: 定义成功用例 TestSpec 固化、成功经验总结、后续执行命中复用、失效、禁用和可观测行为。

### Modified Capabilities

无。

## Impact

- 新增用例执行经验的数据模型、持久化表、repository/store 方法和数据库迁移。
- `execute_run`、`MidsceneCaseAgent` 和规格预览/执行 API 的 TestSpec 复用与经验注入路径。
- 成功 Run 后的经验生成逻辑，依赖已有 LLM 配置并从 ExecutionRecord、TestSpec、阶段断言和 metrics 中提取上下文。
- 前端用例列表、执行确认弹框或用例抽屉中的经验命中提示、查看、禁用和重新翻译入口。
- 单元测试覆盖缓存命中、hash 失效、失败不学习、禁用不注入、人工确认规格优先级和连续失败过期标记。
