## Why

旧文本用例里存在大量抽象、依赖业务背景或预期不可观察的描述。直接进入 Midscene 执行会放大翻译漂移、模型误解和长时间无效点击，试点阶段需要在执行前识别低质量用例，并给出可落地的改写建议。

## What Changes

- 新增“用例可执行性评估”能力，在执行前基于用例文本、项目用例规范、已选 Skill 和成功经验进行评分。
- 对每条目标用例输出质量分、风险等级、阻断原因、可执行性维度明细和改写建议。
- 在执行流中增加质量闸门：高分直接执行，中分提示风险后允许执行，低分默认拒绝执行并给出修正建议。
- 支持用户显式强制执行低分用例，并记录 override 原因，用于调试、试点和评分校准。
- 对同一用例内容、项目规范、已选 Skill 和成功经验上下文未变化的评估结果进行缓存复用，减少重复 LLM 评分和评分漂移。
- 前端执行确认弹框展示评估结果、风险说明和改写草稿；用例抽屉可查看最近一次评估。
- 评估结果写入 run_event / record metrics，便于复盘哪些用例因为描述质量被拦截或带风险执行。
- 不在本阶段自动改写并覆盖原始 Excel 用例；改写建议只作为草稿和人工确认参考。

## Capabilities

### New Capabilities

- `case-executability-gate`: 定义用例可执行性评分、改写建议、执行前质量闸门、人工 override 和可观测行为。

### Modified Capabilities

无。

## Impact

- 新增用例质量评估模型、评分器、LLM prompt 和确定性规则。
- `execute_run` / `trigger_run` 增加执行前评估和低分拦截逻辑。
- API 增加用例评估预览、运行时评估结果、强制执行选项和最近评估查询。
- 前端执行确认弹框、用例抽屉和运行事件展示评估分、阻断原因和改写建议。
- Store / ExecutionRecord / run_event 增加评估结果持久化或序列化字段。
- Store 增加评估版本和上下文指纹，用于安全命中可复用评估缓存。
- 单元测试覆盖评分、阈值、成功经验加分、低分拒绝、override、事件和前端展示。
